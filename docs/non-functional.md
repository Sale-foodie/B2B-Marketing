# 非功能需求

## 1. 性能要求

### 响应时间

| 操作 | 目标 | 说明 |
|------|------|------|
| 页面加载 | < 2 秒 | 首屏渲染（Next.js SSR/SSG） |
| ICP 对话响应 | < 5 秒 | Dify Agent 单轮回复 |
| 搜索任务启动 | < 3 秒 | 从点击搜索到任务开始 |
| 搜索完成 | < 60 秒 | 50 家公司的搜索+详情获取 |
| 线索列表查询 | < 1 秒 | 含筛选和排序 |
| 数据导出 | < 10 秒 | 1000 条以内的 CSV 导出 |

### 并发能力

| 场景 | MVP 目标 |
|------|----------|
| 同时在线用户 | 50 |
| 并行搜索任务 | 5 |
| 数据库连接数 | 20 |

### 数据容量

| 数据类型 | MVP 目标 |
|----------|----------|
| 公司数据总量 | 10 万条 |
| Lead 数据总量 | 50 万条 |
| ICP 数量 | 1000 个 |
| 搜索会话 | 1 万次 |

## 2. 安全要求

### 数据传输

- 全站 HTTPS 加密
- API 请求使用 Token 鉴权
- Dify/n8n 内部通信走内网

### 数据存储

- 数据库密码加密存储
- API Key 通过环境变量管理，不写入代码
- 联系人手机号脱敏存储（展示时部分隐藏）

### 访问控制

MVP 为个人项目，暂时简化：
- 基础的用户认证（邮箱+密码）
- 后续版本加入角色权限（管理员/成员/只读）

### 操作日志

- 关键操作记录日志（搜索、导出、状态变更）
- 日志包含：操作人、操作类型、操作时间、操作对象

## 3. 合规要求

### 《个人信息保护法》合规

| 要求 | 实施方案 |
|------|----------|
| 合法性基础 | 仅采集公开可获取的企业和联系人信息 |
| 最小必要原则 | 仅采集业务必需的字段 |
| 数据来源说明 | 每条数据标注来源渠道 |
| 删除权 | 支持联系人提出数据删除请求 (DSAR) |
| 存储期限 | 非活跃数据 12 个月后自动归档 |

### 《数据安全法》合规

| 要求 | 实施方案 |
|------|----------|
| 数据分类分级 | 公司信息（一般）、联系方式（敏感） |
| 安全保护措施 | 加密存储、访问控制、日志审计 |
| 数据处理记录 | 记录数据的采集、存储、使用、删除操作 |

### 天眼查数据使用合规

- 遵守天眼查 API 使用协议
- 不超范围使用数据
- 不将数据转售给第三方
- 按协议要求的频率和方式调用 API

## 4. 可用性

### MVP 阶段

| 指标 | 目标 |
|------|------|
| 可用性 | 99%（允许每月 ~7 小时停机） |
| 数据备份 | 每日自动备份 |
| 故障恢复 | 4 小时内恢复 |

| 浏览器 | 版本 |
|--------|------|
| Chrome | 最新 2 个主版本 |
| Edge | 最新 2 个主版本 |

### 设备支持

- MVP 优先 PC 端（≥ 1280px）
- 响应式布局，兼顾 Tablet

## 5. 可维护性

### 代码规范

- TypeScript 严格模式
- ESLint + Prettier 统一代码风格
- Git 分支管理（main + feature branches）

### 监控

MVP 阶段基础监控：
- 应用健康检查（Healthcheck endpoint）
- API 错误率监控
- 数据库连接状态
- n8n 工作流执行状态

### 日志

- 应用日志：结构化 JSON 格式
- 错误日志：自动告警（邮件/钉钉）
- 访问日志：Nginx/Vercel 自带
